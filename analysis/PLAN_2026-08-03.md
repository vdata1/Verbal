### Dev-worktree run recipe (verified 2026-08-03)

A worktree's `.git` is a *file* pointing into the main repo, which does not resolve inside a
container — provenance degrades to `unknown-CalledProcessError` and the `scoped_run.sh`
preflight aborts. Mount the gitdir read-only at its original absolute path:

```bash
docker run --rm --cpuset-cpus 0-7 --memory 8g --memory-swap 8g \
  -v /scratch/turcotte/verbal-dev:/app -w /app \
  -v /home/turcotte/projects/verbal/.git:/home/turcotte/projects/verbal/.git:ro \
  verbal:latest <cmd>
```

Verified to record the real commit, and to correctly append `-dirty` when the worktree is
dirty. `:ro` means the container cannot corrupt the main repo's git. `.engine-pins.json` has
already been seeded into the worktree (the entrypoint asserts it, and it is untracked).

**Keep dev containers on low cores** (`0-7`) — the live run owns `8-47`.

## The one judgement call

Phase 0 before everything else is deliberate, and it is the opposite of what the ideas
document is exciting about. The evidence: six drafted reports unfiled, 239 ReDoS nominations
unconfirmed, a headline overstating unique bugs ~80×, and — today — 36% of a window turning

capacity is not the binding constraint; conversion is. Phases 2–4 make the pile grow faster,
which is only good once Phase 1 makes it drain faster.

If time is short, the ordering that maximizes filed bugs is: **0.1 → 0.3 → 1.1 → 2.1**.
